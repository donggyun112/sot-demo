# Semora 0.3 Local Async Integration Design

> Status: approved by the 2026-09-05 instruction to proceed.
>
> This specification supersedes the execution-core and crash-handling portions of
> `2026-09-04-pydantic-ai-local-async-runtime-design.md`. The provider-neutral model boundary,
> AG-UI HTTP/SSE contract, authentication, admission, local supervision, and public event journal
> remain in force.

## Decision

Agent Server uses the released PyPI packages `semora==0.3.0`, `semora-store==0.3.0`, and
`semora-store-pg==0.3.0`. A process-local `RunSupervisor` still owns every active
`asyncio.Task`; there is no worker process, queue poller, or DBOS runtime.

Inside an owned task, Semora's `AgentRuntime` drives the deployment-scoped Pydantic AI `Agent`.
`PostgresSteps` owns effect intent/results, leases, fencing, suspended calls, and queued inputs.
`PostgresTranscript` owns native Pydantic message history and run/model accounting. The existing
`PostgresAgentStore` remains the canonical store for authenticated request admission, abort
intent, interrupt routing, and replayable public AG-UI events.

## Runtime boundary

- A new prompt uses the public AG-UI `runId` as the Semora run ID and the AG-UI `threadId` as the
  Semora conversation ID.
- The final user-message ID is passed as Semora `prompt_id`. Reposting the same canonical request
  after process loss can therefore reacquire the run and continue without redelivering input.
- A duplicate, non-terminal admitted request starts execution only when no local task currently
  owns that run. This is request-driven recovery, not background worker polling.
- Semora contention or fencing does not create a public terminal failure because another attempt
  may own the run. An indeterminate external effect becomes
  `RUN_ERROR(code="indeterminate_execution")`.
- Startup no longer converts all non-terminal requests to errors. They remain replayable and are
  resumed by a canonical duplicate request.

## Tool suspension and resume

Semora, not Pydantic AI's `requires_approval` flag, owns the approval boundary. Server-owned tool
metadata feeds a Semora `ControlPlane`:

- ordinary tools return `Continue()`;
- approval-required tools return `Suspend` with a stable pending ID derived from the native
  run-scoped tool-call ID;
- a refusal remains a model-visible error;
- an approval is revalidated by the current server control plane before execution.

Semora 0.3 does not provide a tool-argument replacement decision at resume time. An approval that
changes the original arguments is therefore denied explicitly instead of silently executing the
original or caller-edited payload.

The AG-UI interrupt table stores the Semora pending ID and origin Semora run ID. A later AG-UI
resume request has its own public `runId`, but routes its answer to the parked origin run. Model
text produced during Semora resume is projected when the resumed attempt completes; prompt runs
continue to project native model/tool events as they stream.

## PostgreSQL

The application migrations install the released 0.3 ledger and transcript schemas used by
`PostgresSteps` and `PostgresTranscript`. The connection pool remains host-owned and is shared by
all three stores. Semora leases are integrity/fencing state, not job ownership.

## Dependency and model policy

All Semora packages are exact 0.3.0 PyPI dependencies; no editable or path source is permitted.
Pydantic AI remains a direct dependency because Agent Server directly consumes its AG-UI,
messages, models, tools, and native `FallbackModel` APIs. Provider selection remains native
Pydantic AI configuration and is injected into the deployment agent unchanged.

## Acceptance

- The runtime port delegates prompt attempts to Semora with exact run, conversation, prompt,
  history, dependency, cancellation, and stream-handler values.
- Approval-required tools suspend durably and authenticated AG-UI resume targets the origin run.
- Duplicate non-terminal admission restarts no more than one local attempt; duplicate live
  admission does not create a second task.
- Semora contention/fencing cannot overwrite the active attempt's public terminal event.
- Indeterminate effects are redacted and surfaced with the dedicated public code.
- PostgreSQL integration tests cover the Semora schema and durable runtime path.
- Unit, integration, Ruff, mypy, lock, package, and Docker verification pass. Live provider tests
  remain credential-gated and are reported separately.
